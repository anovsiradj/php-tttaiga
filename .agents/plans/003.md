# Bulk Update Mechanism Audit & Improvement Plan

## Masalah Teridentifikasi

### 1. Redundansi Seleksi
- **Issue**: Modal bulk update meminta user memilih ulang item yang sudah dicentang di list.
- **Akibat**: User experience buruk; duplikasi effort; potensi kesalahan karena item yang dipilih di modal tidak sync dengan yang dicentang di list.
- **Contoh**: `app-epiks.js:138` – mengambil `selectedIds` tapi tetap fetch ulang via `taigaLoadBulkItems`.

### 2. Sequential Requests (Inefisiensi)
- **Issue**: `taigaExecuteBulk` (taiga.js:754) mengirim PATCH satu per satu secara sinkron.
- **Akibat**: Untuk 100 item, butuh 100x round-trip; waktu total tinggi.
- **Akibat**: Tidak ada mekanisme cancel; jika 1 gagal, sisanya tetap jalan.

### 3. Code Duplication
- **Issue**: 7 modul (tasks, usors, epiks, isus, sprints, projects, members) memiliki implementasi bulk update hampir identik.
- **Akibat**: Maintenance sulit; bug diperbaiki per modul; inkonsistensi fitur.

### 4. Field Terbatas
- **Issue**: Hanya status & assignee yang bisa di-update (epik/usor/isu/task). Tidak ada: description, priority, milestone, epic, subject_prefix.
- **Akibat**: Custom bulk action (prefix) hanya ada di projects; tidak reusable.

### 5. Seleksi Hanya Per Halaman
- **Issue**: Checkbox hanya mencakup item di halaman saat ini.
- **Akibat**: Bulk update hanya berlaku untuk 10-20 item; tidak bisa massal untuk semua filtered items.

### 6. Progress Tidak Konsisten
- **Issue**: Opsi `showProgress` jarang digunakan; tidak ada visual feedback untuk operasi massal.
- **Akibat**: User tidak tahu status; kesan freeze.

### B. Parallel Requests (Performance)

#### Pendekatan:
- Ubah `taigaExecuteBulk` untuk menggunakan `Promise.all` atau `$.when` dengan batch.
- Batasi concurency (misal 10 request paralel) untuk menghindari rate limit.

#### Implementasi:
```javascript
function taigaExecuteBulkParallel(endpoint, items, method, data, onComplete, opts = {}) {
  const batchSize = opts.batchSize || 10;
  const promises = [];
  const results = { success: 0, error: 0 };

  for (let i = 0; i < items.length; i += batchSize) {
    const batch = items.slice(i, i + batchSize);
    const batchPromises = batch.map(item => {
      return $.ajax({
        url: 'api.php' + endpoint + item.id,
        type: method,
        headers: { /* ... */ },
        data: JSON.stringify(data)
      }).then(() => results.success++, () => results.error++);
    });
    promises.push($.when.apply($, batchPromises));
  }

  $.when.apply($, promises).always(() => {
    if (typeof onComplete === 'function') onComplete(results.success, results.error);
  });
}
```

#### Benefits:
- 10 item paralel = 10x lebih cepat dari sequential.
- Rate limit handling via batch size.

### E. Persistent Selection Across Pages

#### Pendekatan:
- Simpan selected IDs di `TTTaiga.selectedItems[type]` secara global.
- Saat load halaman baru (pagination), restore checkbox states berdasarkan global state.
- Master checkbox hanya mempengaruhi item di halaman saat ini (tidak semua).
- Clear selection menghapus global state untuk tipe tersebut.

#### Implementasi:
```javascript
// taiga.js - dalam render function
function taigaRenderItems(items, type) {
  items.forEach(item => {
    const checked = TTTaiga.selectedItems[type].some(s => s.id === item.id);
    $('input[type="checkbox"][value="' + item.id + '"]').prop('checked', checked);
  });
  // Update master checkbox only for current page
  const allChecked = items.every(item => TTTaiga.selectedItems[type].some(s => s.id === item.id));
  $('#masterCheckbox').prop('checked', allChecked);
}

// Update global state on checkbox toggle
$(document).on('change', '.' + type + '-checkbox', function() {
  // add/remove from TTTaiga.selectedItems[type]
});
```

## Rencana Implementasi

### Phase 1: Fix Redundansi Seleksi (Prioritas Tertinggi)
1. Tambah `TTTaiga.selectedItems` global.
2. Modifikasi `taigaBindSelectionLogic` untuk update global state.
3. Ubah `populateBulkUpdateDropdowns` di semua modul untuk baca dari global state.
4. Hapus checkbox di modal; ganti dengan list baca-saja.
- **Status**: ✅ Selesai
- **Catatan**: Global state berfungsi, modal sekarang menampilkan selected items tanpa re-fetch.

### Phase 2: Parallel Requests
1. Buat `taigaExecuteBulkParallel`.
2. Ganti panggilan `taigaExecuteBulk` dengan versi paralel di semua modul.
- **Status**: ✅ Selesai
- **Catatan**: Batch size default 10, progress bar aktif.

### Phase 3: Centralized Component
1. Buat `TTTaiga.BulkUpdate` dengan konfigurasi per type.
2. Migrasi semua modul ke komponen sentral.
3. Hapus duplikasi kode.
- **Status**: ✅ Selesai
- **Catatan**: Semua modul (tasks, usors, epics, issues, sprints, projects) menggunakan `TTTaiga.BulkUpdate`.

### Phase 4: Additional Fields
1. Tambahkan field description, priority, milestone, epic, subject_prefix.
2. Update modal dinamis dan data pengiriman.
- **Status**: ✅ Selesai
- **Catatan**: Field tambahan sudah ada di config dan markup; terapkan sesuai type.

### Phase 5: Persistent Selection Across Pages
1. Implementasi global state `TTTaiga.selectedItems` untuk menyimpan selected IDs lintas halaman.
2. Restore checkbox state saat render (pagination).
3. Master checkbox hanya untuk halaman saat ini.
4. Clear selection reset global state.
- **Status**: ✅ Selesai
- **Catatan**: Selection persist saat pindah halaman; master checkbox hanya pengaruhi halaman saat ini.

## Dampak & Resiko

### Positive:
- UX lebih baik (tidak perlu pilih ulang).
- Performa lebih cepat (paralel).
- Maintenance lebih mudah (sentralisasi).
- Fitur lebih kaya (field tambahan).

### Resiko:
- **Breaking Change**: Modifikasi `taigaBindSelectionLogic` bisa mempengaruhi modul lain.
- **Rate Limit**: Parallel request bisa terkena limit API; perlu batch size.
- **State Management**: Global state harus di-reset saat filter berubah.

### Mitigasi:
- Uji di environment development dulu.
- Batch size 5-10 untuk aman.
- Reset `TTTaiga.selectedItems` saat filter atau halaman berubah.
