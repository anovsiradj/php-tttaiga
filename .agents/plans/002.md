# Plan 002: php-skit & web-skit Implementation Roadmap for TTTaiga (REVISED)

## Current State Analysis

### Project: TTTaiga
- **Type**: PHP proxy/dashboard for Taiga API
- **Stack**: PHP 8.4 + Bootstrap 5 + jQuery
- **Structure**: Flat file-based routing (projects.php, tasks.php, etc.)

### Existing Integrations ✅
- **php-skit**: `CURL` class (api.php:168), `App` class (app/helpers/App.php)
- **web-skit**: Dark mode widget, some utility classes
- **wiet**: Web Component factory (`vendor/anovsiradj/wiet/wiet.js`) — template loading, Shadow DOM, event delegation, lifecycle hooks
- **Features**: Bulk CRUD, Shared filters, Shared input, API caching, Session auth

---

## AUDIT FINDINGS (2026-08-21)

### REJECTED Items
1. **Routing System** — VIOLATES flat architecture vision in AGENTS.md. TTTaiga is a simple proxy, not a framework. KEEP file-based routing.
2. **CLI Commands** — LOW PRIORITY. Bulk ops already work via UI. CLI only useful for cron/automation. Defer indefinitely.
3. **Asset Bundling** — MARGINAL GAIN for internal tool. Not worth the complexity.
4. **Full Lakra.js Migration** — HIGH REGRESSION RISK. Rewrite all app-*.js = massive effort. Pilot first on 1 small module only.

### ADDED Items
1. **Shared Filter Extraction to php-skit** — Core differentiator, aligns with visi/misi.
2. **Shared Input Utilities to web-skit** — `populateDropdowns`, `_populateList`, append `<option>` pattern.
3. **Lakra.js Pilot** — Single module test before any broader adoption.
4. **Testing Strategy for Lakra** — Browser test coverage requirement.
5. **Rollback Plan** — Mandatory for any Lakra experiment.

**Timeline: 2 weeks**

3. **CURL Class Enhancement**
   - [ ] Chainable methods instead of manual `opt()` calls

4. **Wiet Foundation**
   - [ ] Identify top 3 most-copied inline HTML patterns in JS

- Middleware filters requests correctly
- All existing functionality preserved

## Key Principles

1. **Flat Architecture First** — No routing frameworks, no MVC, no controllers. File-based routing stays.
2. **Incremental Migration** — No big-bang rewrites. Every change must be reversible.
3. **Test Before Adopt** — Lakra pilot MUST pass browser tests before broader rollout.
4. **Extract to Libraries** — Shared filter/input patterns belong in php-skit/web-skit, not duplicated per module.
5. **Pragmatic Over Perfect** — Internal tool prioritizes function over polish. Skip asset bundling, skip themes unless needed.

## Risks & Mitigations

| Risk | Impact | Mitigation |
|------|--------|------------|
| Lakra.js regression | High | A/B toggle, browser tests, rollback plan |
| Wiet component rendering issues | Medium | Browser tests, fallback to `<template>` |
| Shared filter breaks cross-module | Medium | Integration tests, manual QA checklist |
| Config migration breaks env-specific settings | Medium | Test in all environments before merge |
| php-skit extraction too aggressive | Low | Keep backward-compatible wrappers |
